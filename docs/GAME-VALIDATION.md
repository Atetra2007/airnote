# v0.3 本机游戏验证 · 2026-09-24

测试对象：已部署的原版 `v0.3.0-preview.1`，提交 `158688b`。游戏处于真实三角洲客户端的口琴手动演奏界面。结果区分程序状态、进程权限读取和用户听到的声音；不以程序显示“播放完成”代替游戏验收。

## 本机部署

- 桌面“口琴小曲库”快捷方式已切换到 `HarmonicaDesk-0.3.0-preview.1/App/HarmonicaDesk.exe`；旧 v0.2 安装保留。程序产品版本为 `0.3.0-preview.1+158688be326ad86ec5c45c0ba38c66e0712434aa`。
- 部署时核对解压目录 410 个允许清单文件，并确认原有 15 份个人曲谱保持不变；升级前已备份快捷方式和个人数据。
- 原 ZIP 的 SHA-256 再次与旁置摘要文件匹配：`07f5c54e2e280ddfc843a0876a8bae727809c1b7f6c3ca77cc92c79d4866fae2`。本次验收文档更新没有重建或替换程序包。

## 自动演奏与权限

| 项目 | 结果与证据 |
| --- | --- |
| 游戏手动模式 | 实际画面确认显示 `Z X C V B N M ,` 八个音键；用户确认亲手按 Z 有声音。仅取出口琴但仍处于游戏自带自动演奏模式，不满足测试前提。 |
| 普通权限播放器 → 管理员游戏 | 原创“停止与取消”谱完整运行 32 秒，程序显示“播放完成”，无本轮前台切换报错；用户确认全程没有声音。 |
| 权限差异 | 通过只读 `TokenIntegrityLevel` 查询，游戏为 High（12288），原播放器为 Medium（8192）。 |
| 相同版本、相同权限复测 | 用户明确授权仅本次管理员测试；正常关闭普通权限实例后，启动原版 v0.3。再次读取确认两者均为 High（12288）。用户选择同一谱、游戏保持手动口琴界面并按 F6，确认听到三个长音。 |
| F8 中断长音 | 用户在第一个长音发声期间按 F8，确认立即停止。 |

本机对照支持：此次“程序播放完成但游戏无声”由运行权限不一致导致。结论限定于这台电脑、本次游戏状态和三个长音样本，尚不代表整首歌曲、音准或全部鼠标组合通过。

期间曾在独立目录试验普通 SendInput 扫描码编码，仍运行于 Medium 权限；未证明修复有效，实验实例已关闭，源码已撤回。正式桌面程序和快捷方式没有替换为实验版，未将快捷方式设为永久管理员运行。

## 跟谱手弹

用户选择“跟谱手弹 → 节奏跟弹”，在游戏中按 F6 后确认浮窗正常显示并走谱；Alt+Tab 切出会暂停，切回游戏保持暂停，需再次按 F6 才继续。此项为用户实际操作确认。

## 验证限制与后续

- 同权限复测的发声结果由用户听辨确认，未录制或分析游戏音频。
- 界面控制工具运行于普通权限；对管理员游戏的按键和窗口切换出现无响应，对管理员播放器无法读取完整控件树。实际操作不成功时没有把工具返回成功当作游戏已接收输入。
- 原先的“前台窗口已经变化，演奏已停止”错误与多次切换窗口对应；受控长音测试期间保持游戏前台，未再出现该错误。
- 尚未完成真实鼠标左／中／右键与音键组合、连续同音、实体长按重复、按住实体音键时停止、浮窗穿透、主窗最小化、跨屏与 DPI、完整歌曲听校。
- 本次只对原版程序进行了临时管理员启动，不改变 UAC、游戏保护、系统安全设置或永久启动权限。
