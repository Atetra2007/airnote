# v0.3.0-preview.2 演奏节奏修复 · 2026-09-24

用户在 preview.1 中反馈多首歌曲衔接过紧、旋律听起来异常。此前三个长音与 F8 测试只证明基本输入可达游戏，没有验证歌曲编配和换音效果。

## 曲谱复核

- 58 首固定来源重新核对原始大小、SHA-256、解析和时长；48 首社区谱再次以独立 Python 有理数解析逐项比较音高、休止、时值和顺序，全部一致。
- 本机 21 首已下载来源歌曲逐事件与来源一致，BPM 相同。没有发现转换器丢失休止，也没有覆盖个人谱面。
- 社区转换谱均使用 10 ms 留白，接近连奏。原输入实现连续发送鼠标修饰键和音键，没有给游戏读取音区／升音状态的时间。
- 对照[固定来源的输入时序说明](https://github.com/JikoSchnee/delta-harmonica-macro/blob/9072cc92e3bd88d5a51c694335d6243734530a09/app.js#L97)，其单独说明了换音留白和鼠标修饰键预置。本项目独立实现等待与取消控制，未并入来源程序。
- 原版实时时钟的无输入测试：79 个目标 10 ms 间隔，最短 9.127 ms，中位 10.011 ms，没有测得零间隔。因此没有把普遍的“系统吞掉全部间隔”当作已证实根因；延迟处理由可控故障测试覆盖。
- 《诀别书》含最短约 10.42 ms 的音，《土耳其进行曲》约 15.63 ms；一些来源休止低至约 1.56 ms。来源一致不代表这些时值适合游戏或符合原曲录音。

## 修复行为

1. 设置增加“游戏换音留白”，默认 60 ms，范围 0–250 ms。实际值为曲谱间隔与“目标留白、音符时值四分之一中的较小值”两者的较大值；0 恢复仅用曲谱间隔。只缩短音符按住部分，不增加正常时间轴的拍数。已有休止完整保留。
2. 鼠标音区／升音组合先按修饰键，等待至少 24 ms 后才按音键。等待计入该音原时值；取消或失去游戏前台时不会继续按音键，并沿用异常释放流程。
3. 实际松键较晚时，后续音不挤占已经设定的留白；休止从实际静音时间起完整经过。发生调度延迟时允许实际总时长稍长，优先避免赶拍，不修改谱面 BPM。
4. 在倒计时和输入前检查短音是否还能保留 12 ms 的按住时间。默认设置下 56 首通过模拟时间轴检查；两首上述极短音曲目会提示具体音符，仍可编辑和本地试听，不偷偷删除音符或拉长整首歌曲。

## 验证与边界

- 构建回归：Core 104/104、Windows 41/41、Desktop 存储 18/18；36 组组件布局／渲染检查通过。自包含程序 410 个允许清单文件通过打包核验。
- 修复后的真实单调时钟与无输入记录器：100 ms 快音按四分之一时值取 25 ms 留白，79 次换音最短 25.007 ms、中位 25.026 ms，没有低于目标的间隔；8 秒谱面加 3 秒倒计时实际运行 11.050 秒。此记录器不发送游戏按键或音频。
- Windows 回归包括重复音留白、显式休止、延迟松键、不赶发、鼠标预置、预置期间停止／切出、正常时间轴无累计额外预置时长和极短音拒绝。
- 设置升级保留旧热键与数据，新留白值重启持久化；0 值有效，越界值回退默认值。
- 设置界面检查覆盖浅／深主题、100%／150%／200% 组件渲染。本机长音游戏测试仍属于 preview.1，不能用于证明本次修复的实际听感。
