# v0.3 跟谱验证记录

验证环境：2026-09-24，Windows x64，.NET SDK 10.0.300。功能直接加入原有 WPF「口琴小曲库」，沿用曲库与个人设置。以下区分逻辑、组件、桌面窗口和游戏证据。

本文主要记录 preview.1；preview.2 的游戏演奏时序修复与复核结果见 [RHYTHM-VALIDATION.md](RHYTHM-VALIDATION.md)，不将旧版游戏测试自动计入新版听感验收。

## 逻辑与存储

- 三组原有测试继续运行，并新增完整拍数时间轴、等键状态、标准指法、升音／音区／鼠标组合、休止、长音、连续同音、长按重复、已按住的键、倒计时取消、暂停恢复、定位、倍率、A/B 含尾音和单音循环检查。
- 十万音符时间轴完整遍历后停在正确结束点；等键模式即使时钟前进很久也不会跳过未弹音符。
- Raw Input 的键鼠结构大小、字段偏移、组合按钮标志和键盘 break/repeat 解码均有测试。普通移动包不清空鼠标状态，组合 down/up 不遗留“按住”状态。
- IL 调用图检查从跟谱引擎、Raw Input 和目标校验出发，没有通向自动演奏、模拟输入或音频输出的调用路径。
- 旧设置缺失／null 字段回退默认值，保留原开始／停止热键；跟谱模式、倍率、背景、负屏幕坐标及尺寸重启持久化有存储测试。

完整合并后的回归结果：Core **104/104**、Windows **35/35**、Desktop 存储 **17/17**，Python **10/10**。曲库检查通过 **58** 条固定来源记录及 **3** 份原创示例。倒计时结束但尚未通过游戏前台检查时，暂停不会消耗曲谱时间；对此另有回归测试。

## 组件布局与长谱绘制

命令：`dotnet run --project tests/Harmonica.LayoutChecks -c Release`。

- 36 组检查通过：主窗最小／默认尺寸、浮窗 440×240／560×280、100%／150%／200% DPI 渲染、深浅主题、35%／75%／95% 背景，以及设置冲突提示布局。
- 关键控件位于边界内，互不重叠；当前完整组合键、倍率与快捷键文字未裁切。
- A/B 在全曲结束前完成时，不显示片段外音符为“当前音”。
- 十万音符曲谱执行 1,200 次可见区域绘制，最近一次为 4,589 ms，GC 后托管内存增量 51,632 字节。这是本机组件绘制样本，不是游戏帧率、整进程内存上限或长时间游戏性能承诺。
- 组件检查不显示窗口、不注册监听、不操作系统缩放。图片和机器可读结果在本机 `artifacts/guide-validation/components`，不能代替跨屏实测。

- 将 ZIP 解压到独立目录，直接启动包内 `App/HarmonicaDesk.exe`，使用 `--data-dir local/guide-final-qa` 隔离个人数据；首次呈现日志为 512 ms，修复后重新启动为 479 ms（两次本机样本）。版本资源为 `0.3.0-preview.1` / `0.3.0.0`。
- 实际完成本地试听播放到结束、切换等键模式、0.75 倍速保持原 BPM、A=B 单音片段、循环开关、停止返回 A、切歌清空片段，以及未下载曲目禁用跟谱。未下载曲目的旧音符数量也已清除。
- 从独立测试配置注册开始／停止／浮窗快捷键；开始有倒计时，无游戏前台时显示提示并保持暂停。隐藏／显示不会自动开始，背景可调至 95%。测试使用 `Ctrl+F9 / Ctrl+F10 / Ctrl+F11`，避开本机原安装实例的全局热键；产品默认仍为 F6／F7／F8。
- 实际缩放到 440×240，当前组合键与下一音可见；主窗最小化后，调整状态的独立浮窗仍显示。重新启动仍默认本地试听，进入跟谱后恢复等键模式、0.75 倍速、95% 背景和 440×240 尺寸。标题拖动后左上位置从 `(100,48)` 改为 `(340,228)` DIP，落盘值一致；标题拖动使用独立 Thumb，避免原生移动循环干扰。实际截图保存在本机 `artifacts/guide-validation/live/final-main.png`、`final-overlay-min.png`。
- 原生隐藏窗口检查 **30/30**：实际 HWND 的 layered／transparent／noactivate／toolwindow 标志正确，解锁再锁定正确，屏幕外坐标可回到当前工作区，退出销毁 HWND。没有以此代替游戏穿透或实机热插拔。
