统计与待办由 `scripts/catalog_status.py` 生成，构建时用 `--check` 拒绝陈旧的生成文件。见[当前状态](CATALOG-STATUS.md)和[221 个待核作品](CALIBRATION-QUEUE.md)。历史运行时报告有各自的目录哈希，不用旧数字证明本轮状态。

## B 批证据盘点与下一步

本轮复核四首已有录音、来源谱和缓存分析的来源关系及文件哈希，没有重新运行音频模型，也没有据此提升曲库标签。四份 WAV 与转换记录、原始 WEBM 与取得记录的哈希均一致。完整本机报告见 `local/catalog-0.4.1/batch-b/report.md` 与 `report.json`。

| 曲目 | 当前可用证据 | 下一步核对 |
| --- | --- | --- |
| SAIKAI | 当前人声缓存中，34.31–40.27 秒有连续六个候选音高与来源谱在移调 −7 半音后对应 | 优先核对这句的起音、2.44 秒空档、重复音间的 0.67 秒空档及后接候选音；六音对应不代表时值通过 |
| 远航星的告别 | 上游版和洲洲版在移调 −1 半音后有较宽范围旋律候选 | 缩至一个完整短句，逐个复核起止、重复音和休止；不采用整段匹配率作为校准结论 |
| His Theme | 两个洲洲版本已核对来源；人声分离缓存只有 0.04 秒共同音高证据、没有稳定音符段 | 对原混音的一小段器乐主旋律重新分析；同作品组的社区版本本轮未逐音核对 |
| 飞鼠进行曲 | 人声分离缓存没有可用音高帧或稳定音符段 | 改用原混音中的器乐主旋律，先完成短段定位再处理时值 |

His Theme 与《飞鼠进行曲》的旧“0 音匹配”来自没有可用目标音符，不能解释成谱面旋律错误。四首仍待音乐复核。后续优先完成上述短句，避免继续扩大未核准候选的数量；A 批听感反馈到位后按具体秒数修正，真实游戏检查另行记录。

## 可复现的本机核验

以下核验需要已有本地曲谱、来源录音与证据缓存。它们不下载素材、不覆盖原谱、不发出键鼠或音频。输出目录必须是尚不存在的新目录。

```powershell
& 'C:\Program Files\dotnet\dotnet.exe' run --file scripts/Audit-SelectedScores.cs -- (Get-Location).Path 'D:\projects\delta force\local\catalog-0.4.1\batch-a-audit-new'
python scripts/prepare_listening_review.py local/catalog-0.4.1/batch-a-audit-new/audit.json
```

第二个脚本需要已有的 `numpy`、`soundfile`，只生成本地复核文件。第三方音频、完整曲谱和听辨页均不加入发行包。
